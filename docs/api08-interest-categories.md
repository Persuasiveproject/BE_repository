# API #8 관심 카테고리 중복 처리 보충 계약

결정일: 2026-11-17. 사용자 요청에 따라 API 수정1에서 보류했던 중복 ID 처리 정책을 아래와 같이 확정한다. 적용 대상은 `PUT /v1/me/interests` (`FC-AU-120-003`)다.

- `categoryIds`는 필수 배열이며 null을 허용하지 않는다. 각 요소는 기존과 같이 양의 64비트 십진 ID 문자열이어야 한다.
- 모든 요소의 형식을 검증한 후 중복 ID를 제거한다.
- **중복 제거 후 서로 다른 ID가 0~5개이면 허용한다.** 원본 배열 길이가 5를 초과해도 같은 규칙을 적용한다.
- 중복 제거 후 6개 이상이면 `400 INTEREST_LIMIT_EXCEEDED`를 반환하고 기존 저장값을 변경하지 않는다.
- 대상 카테고리 존재·활성 여부 검증, ACTIVE 회원 권한, 사용자 행 잠금 및 전체 교체 처리는 유지한다.
- 성공 응답은 기존의 `200 {data:{interests:Category[]}}`를 유지하며 ID는 문자열이다. Category의 필수 필드는 `id`, `name`, `sortOrder`다.

예: `["1","1","1","1","1","1"]`은 대상 카테고리가 존재하고 활성 상태라면 1개로 저장한다. 서로 다른 5개를 반복한 배열은 5개로 저장한다. 서로 다른 6개가 포함된 배열은 거절한다.

이 문서는 사용자 합의에 따른 보충 계약이다. Drive의 API 수정1 원본 파일은 이 변경에서 수정하지 않았다.
